# 스캔 — 자료를 처음부터 다시 만들기

페이지가 읽는 JSON 은 전부 폴리곤 체인에서 긁어 만든 것입니다.
시간이 지나면 낡으므로, 여기 있는 두 명령으로 다시 만듭니다.

```bash
cd scan
python scan.py all      # 체인에서 원자료 긁기 (raw/ 에 쌓임) — 2~4시간
python build.py         # 원자료를 페이지용 JSON 으로 — 2~3분
```

`build.py` 가 끝나면 상위 폴더의 JSON 이 갈아 끼워집니다. 페이지는 새로고침만 하면 됩니다.

## 나눠서 돌리기

`all` 은 네 단계를 순서대로 돕니다. 오래 걸리는 것부터라 중간에 끊겼다면 그 단계만 다시 돌리면 됩니다.

| 명령 | 무엇을 | 대략 |
|---|---|---|
| `python scan.py dect` | DeCT Right 발급 기록 (발급지갑 5곳) | 40분 · 190만 건 |
| `python scan.py cc2c` | CC2C 수금지갑 입금 | 90분 · 390만 건 |
| `python scan.py mpc`  | MPC 토큰 전송 전량 | 10분 · 18만 건 |
| `python scan.py flow` | 주소별 자금흐름·가스비 | 60분 · 1,100명 |

`flow` 는 `mpc` 와 `dect_top_c.json` 이 있어야 대상을 정할 수 있으니 마지막에 돕니다.

## 알아둘 것

- **API 키** — `config.py` 의 기본값 대신 환경변수를 쓰는 편이 안전합니다.
  ```bash
  export POLYSCAN_KEY=본인키
  ```
  무료 키는 **초당 5회**가 한도입니다. `WORKERS` 를 6보다 올리면 오히려 느려집니다.

- **NOTOK 은 끝이 아닙니다.** rate limit 일 때도 같은 응답이 옵니다. 이걸 끝으로 오인하면
  데이터가 조용히 잘립니다 — `api.get()` 이 재시도로 처리합니다.

- **대형 지갑은 끊습니다.** 거래가 수만 건인 지갑은 `PAGE_CAP`(기본 40쪽 = 4만 건)에서
  멈추고 `cut:1` 로 표시합니다. 이게 없으면 한 주소에서 몇십 분씩 멈춥니다.

- **원자료는 지우지 마세요.** `raw/` 에 남겨 두면 `build.py` 만 다시 돌려
  판정 기준(아래)을 바꿔 볼 수 있습니다. 체인을 다시 긁을 필요가 없습니다.

## 바꿔볼 만한 값 (`config.py`)

| 값 | 지금 | 뜻 |
|---|---|---|
| `CREDIT_MULT` | 2.4 | 앱의 「신용매매 결제대금」 ÷ 실제 낸 결제대금. 앱 화면 3건으로 맞춘 값이라 시기가 다르면 어긋날 수 있습니다 |
| `USDT_KRW` | 1400 | USDT 원화 환산. `../config.json` 과 같이 고쳐야 화면과 어긋나지 않습니다 |
| `PAIR_SEC` | 2400 | IDM 과 CC2C 입금을 같은 참여로 볼 시간창(초) |
| `FREE_KPD` | 5000 | DeCT 1당 낸 돈이 이 밑이면 「자기돈 거의 없음」 |
| `FLOW_TOP` | 700 | 자금흐름을 훑을 DeCT 상위 인원. 늘리면 정확해지지만 그만큼 오래 걸립니다 |

## 만들어지는 것

| 파일 | 내용 |
|---|---|
| `addr_idx.json` | 전체 주소 지표 — 검색과 관계도가 이걸 씁니다 |
| `dect_top_c.json` | DeCT 상위 1500 상세 |
| `flow.json` | 주소별 자금흐름 + 가스비 공급자 |
| `gas_hub.json` | 둘 이상의 지갑에 가스비를 댄 주소 |
| `sut_src.json` · `sut_hub.json` | SUT 유입처와 공급 허브 (자금흐름에서 파생) |
| `mpc_lock.json` · `mpc_esc.json` | 에스크로 잠긴 매물·실제 인도 |
| `meta.json` | 기준 시각과 적용된 설정값 |

`meta.json` 의 시각이 화면에 「○○ 기준」으로 표시됩니다.
